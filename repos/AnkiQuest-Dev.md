## This repository

AnkiQuest-Dev is the development environment for every AnkiQuest repository, on any machine: one dev shell per kind of repository (`devShells.<system>.{default,server,desktop,gallery,android,android-emulator,android-backend,anki}`), NixOS on WSL (`nixosConfigurations.ankiquest-wsl`), modules for NixOS and nix-darwin, a winget configuration for Windows, a dev container, and the reusable workflows and label set every repository shares. The other repositories' flakes take their shells, formatter and pins from here.

- **Layout.** `flake.nix`: the outputs (`lib`, `overlays`, `packages`, `devShells`, `nixosModules`, `darwinModules`, `nixosConfigurations`, `checks`). `shells/toolchains.nix`: every pinned version (Rust, Android SDK and NDK, JBR, Node, Python), each next to the repository file it follows. `shells/default.nix`: the dev shells. `nixos/roles` and `nixos/modules`: what a NixOS machine needs, exported as `nixosModules.ankiquest-dev`; `nixos/hosts/ankiquest-wsl`: the WSL host. `darwin/`: `darwinModules.ankiquest-dev`. `windows/`: the winget configuration, generated from `shells/toolchains.nix`. `.devcontainer/`: the dev container. `tools/banner`: `ankiquest-banner` (`packages.banner`), the README banner and social preview tool every repository uses, a Cargo workspace of its own.
- **One source.** Shared Nix tooling (toolchain pins, dev shells, formatter and its check, nix-ld and direnv) lives here only; other repositories take it as the `ankiquest-dev` input. A repository's own packages and NixOS service modules stay in that repository, so nothing here depends on another AnkiQuest repository.
- **Shared workflows.** Workflows more than one repository runs are reusable workflows in `.github/workflows/` (`android-ci`, `android-nightly`, `banner`, `nix-check`, `labels`, `conflict-scan`, `pr-labels`, `issue-labels`); `labels.json` is the shared label set, tested by `tests/labels.test.ts`. `ankiquest-labels.yml` is the caller the other repositories copy. A change here reaches every caller: check them. A change to `ankiquest-banner` that changes pixels makes every caller's banner stale; redraw them in each repository.
- **Pins follow the repositories.** When a repository changes a version it pins (`rust-toolchain.toml`, `gradle/libs.versions.toml`, `gradle/gradle-daemon-jvm.properties`, a CI workflow), change the matching value in `shells/toolchains.nix` and regenerate `windows/configuration.dsc.yaml` (`nix build .#windows-configuration`). Update one flake input at a time with `nix flake update <input>`.
- **Nix only.** Configuration is Nix, formatted with alejandra. Generated files come from Nix expressions or Rust. Shell and PowerShell stay a few lines of glue; anything larger becomes Rust.
- **Nothing private.** Signing keys, `keystore.properties`, `google-services.json`, tokens and proprietary SDKs (the Garmin Connect IQ SDK) are installed by hand, as the README says, and never committed.
- **Checks to run** before pushing: `nix flake check --all-systems`, `alejandra --check .`, `nix develop .#<shell>` for each shell you changed, `nix develop -c actionlint`, `nix develop .#gallery -c node --experimental-strip-types --test tests/*.test.ts` for the label workflows, and `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` in `tools/banner` for the banner tool.
