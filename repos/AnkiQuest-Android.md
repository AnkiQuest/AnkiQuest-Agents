## This repository

AnkiQuest-Android is AnkiDroid with AnkiQuest added.

- **Where AnkiQuest lives.** AnkiQuest code is in `ankiquest-core/` (server client and shared rules, no dependency on `:AnkiDroid`), `ankiquest-ui/` (views, widgets, notifications, art and their resources, on top of core), `AnkiDroid/src/main/java/com/ichi2/anki/ankiquest/` (activities and the hooks into AnkiDroid), `ankiquest_*` resources and `.github/workflows/ankiquest_*`. The package stays `com.ichi2.anki.ankiquest` in every module. AnkiQuest Lite, for stock AnkiDroid users, comes as a third module on top of core and ui: the `:lite` app, package `org.ankiquest.anki.lite` (#422). Code ownership covers upstream AnkiDroid code too: codebase quality comes before avoiding conflicts with upstream AnkiDroid. Change upstream code when it makes the code better, resolve the resulting conflicts in the upstream merge PRs, and say in the PR which upstream code changed.
- **Upstream merges** come in as merge commits that keep upstream history (this overrides upstream's linear-history rule). Never squash or rebase them. When upstream changes `AGENTS.md` or `CLAUDE.md`, keep ours and fold in any upstream rule that still applies, in this section. Upstream's [AI policy](AI_POLICY.md) disclosure rules (`Assisted-by`) apply here too.
- **Server data is pinned.** API examples and shared fixtures are copied from one server commit (`ankiquest-core/src/test/resources/ankiquest-server.sha`); see [docs/ankiquest-server-snapshot.md](docs/ankiquest-server-snapshot.md). The workflows fetch it from AnkiQuest/AnkiQuest-Server; commits from before the split (AnkiQuest/AnkiQuest-Desktop#306) have the same hashes there. The bump PR brings server changes in; whoever's server change breaks it fixes it. The examples Android reads are listed in `ankiquest-api/names.json`.
- **Unit tests run on the JVM.** Robolectric unit tests run on the JVM, not Android's runtime: regex (ICU), text, locale and other platform behaviour can differ. Code that depends on such behaviour needs a test in the emulator suite (`AnkiDroid/src/androidTest`), and lint errors are not to be suppressed without a comment saying why.
- **README banner and social preview.** `cargo run --release --manifest-path tools/ankiquest-banner/Cargo.toml -- --record` regenerates `docs/graphics/logos/banner_readme.png`: it records `AnkiquestBannerScreenshots` with Roborazzi (sample data, pinned clock, fixed device) and composes the banner with the bundled Roboto. The `ankiquest README banner` workflow fails a pull request that touches the banner or its tooling unless the committed banner has the same pixels, and proposes a new banner for each release. `docs/graphics/logos/social_preview.png` comes from the pinned server: `cargo run -p ankiquest-xtask -- banner --social --out <this checkout>/docs/graphics/logos/social_preview.png` in AnkiQuest-Server; the `ankiquest art check` workflow fails unless the bytes match. The store screenshots in `fastlane/` are still upstream AnkiDroid's.
- **CI on PRs runs Ubuntu only.** macOS and Windows run on `master` and nightly. For changes to Gradle, test setup or native libraries, dispatch the unit test workflow with all three systems before merging.
- **Checks to run** before pushing: `./gradlew ktlintCheck` and the unit tests you touched (`./gradlew :AnkiDroid:testPlayDebugUnitTest --tests '…'`). Leave the full suites to CI.
