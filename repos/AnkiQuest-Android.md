## This repository

AnkiQuest-Android is AnkiDroid with AnkiQuest added.

- **Where AnkiQuest lives.** AnkiQuest code is in `ankiquest-core/` (server client and shared rules, no dependency on `:AnkiDroid`), `ankiquest-ui/` (views, widgets, notifications, art and their resources, on top of core), `AnkiDroid/src/main/java/com/ichi2/anki/ankiquest/` (activities and the hooks into AnkiDroid), `ankiquest_*` resources and `.github/workflows/ankiquest_*`. The package stays `com.ichi2.anki.ankiquest` in every module. AnkiQuest Lite, for stock AnkiDroid users, comes as a third module on top of core and ui: the `:lite` app, package `org.ankiquest.anki.lite` (#422). Code ownership covers upstream AnkiDroid code too: codebase quality comes before avoiding conflicts with upstream AnkiDroid. Change upstream code when it makes the code better, resolve the resulting conflicts in the upstream merge PRs, and say in the PR which upstream code changed.
- **Upstream merges** come in as merge commits that keep upstream history (this overrides upstream's linear-history rule), merged outside the merge queue. Never squash or rebase them. Upstream's `AGENTS.md` is kept in the "Upstream guidance" section at the end of this file. Upstream's [AI policy](AI_POLICY.md) disclosure rules (`Assisted-by`) apply here too.
- **`upstream-main`** is ankidroid/Anki-Android `main`, kept current by AnkiQuest-Sync's `mirror` job. Start `upstream/*` branches from it; never commit to it.
- **Nothing published as AnkiDroid.** AnkiQuest publishes nothing under AnkiDroid's `com.ichi2` namespace: no application id, provider authority, permission, intent action or Maven group starting with `com.ichi2.anki`, and no build meant to replace or pose as AnkiDroid. Our names start with `org.ankiquest`; AnkiQuest/AnkiQuest-Android#461 tracks the move.
- **Server data comes from server master.** The unit tests read AnkiQuest-Server's API examples and shared fixtures from its `master`: `node .github/ankiquest_server_data.cjs fetch` copies them into the test resources (`ankiquest-api/` and `ankiquest/`, not committed), and every workflow that runs the unit tests does so first; see [docs/ankiquest-server-data.md](docs/ankiquest-server-data.md). `ankiquest-api/names.json` lists the examples Android reads (`consumed`, `boards`, `challenges`), those it doesn't read (`unused`) and those it doesn't read yet (`not_yet`); a server example it doesn't list counts as `not_yet`. A server change that breaks these tests is fixed in the same change, or Android is updated right after.
- **Unit tests run on the JVM.** Robolectric unit tests run on the JVM, not Android's runtime: regex (ICU), text, locale and other platform behaviour can differ. Code that depends on such behaviour needs a test in the emulator suite (`AnkiDroid/src/androidTest`), and lint errors are not to be suppressed without a comment saying why.
- **README banner and social preview.** `ankiquest-banner --server . --record` (AnkiQuest-Dev's shared tool) regenerates `docs/graphics/logos/banner_readme.png` and `social_preview.png` from `docs/graphics/banner.toml`: it records `AnkiquestBannerScreenshots` with Roborazzi (sample data, pinned clock, fixed device), then draws five phones and the duo master of the pinned AnkiQuest-Art release (its `masters.zip` unzipped into `art/`). The `ankiquest README banner` workflow records the screens, passes them to AnkiQuest-Dev's `banner.yml`, fails a pull request that touches the images or their inputs unless the committed images have the drawn pixels, and proposes new images for each release. The store screenshots in `fastlane/` are still upstream AnkiDroid's.
- **CI on PRs runs Ubuntu only.** macOS and Windows run on `master` and nightly. For changes to Gradle, test setup or native libraries, dispatch the unit test workflow with all three systems before merging.
- **Checks to run** before pushing: `./gradlew ktlintCheck` and the unit tests you touched (`./gradlew :AnkiDroid:testPlayDebugUnitTest --tests '…'`). Leave the full suites to CI.
